Long-Running Workflows: Subagents, Background Jobs, Memory

Break work into small bounded tasks; orchestrate the rest

notes by Ishaan ✏️

~ 14 min read ~

Up to now, every Claude interaction in this course has been you and one Claude in a tight loop. This lesson is about the next level: workflows where multiple Claudes run in parallel, in the background, across hours, with handoffs between them.

Mental model: Claude works best in small bounded tasks
A 4-hour Claude run is not 240 1-minute Claude runs in a row. It is 240 chances for context to drift, an assumption to harden, or an early mistake to compound. The mental model: **break every long workflow into small bounded tasks with explicit handoffs**. Each task knows its input, its scope, its expected output, and its hard stop. Each handoff is a small artifact a human or another agent can read in 60 seconds. This is exactly how you would run a real engineering team, and Claude responds to the same shape.

Move 1: The Parallel Fan-Out Pattern

  • When you have a task that decomposes into N independent sub-tasks, do not run them in sequence. Fan out N subagents in parallel, each with a bounded brief, each writing a small artifact, and merge at the end.
  • Decompose: Independent slices: auth code, database queries, API routes, env-var usage, third-party deps.
  • Brief each subagent: Each gets one slice + a hard scope + the 5-bullet artifact format + a 10-minute soft cap.
  • Launch in parallel: 5 Task tool calls in one message. Each runs in its own context window with bounded budget.
  • Wait for artifacts: Each writes to docs/audit/<area>.md. The orchestrator does not babysit — it waits for the deliverables.
  • Merge: The orchestrator reads 5 artifacts (5 short docs), produces one ranked findings doc with severity.
  • Human review: You read the merged doc. The 5 raw artifacts are there for drill-down. The whole audit took 12 minutes.

Move 2: The Artifact-Handoff Protocol

  • Long workflows fail because context dies. A 4-hour run accumulates 200K tokens of stdout, of which maybe 5K are signal and the rest is noise.

Traps to flag for the exam

The classic trap: the runaway loop: The single most expensive mistake in orchestration is **the runaway loop**: an agent that keeps going past its useful scope because the stop condition was vague. A loop told to *'fix the test failures'* with no scope might decide that fixing tests requires refactoring the test framework. Forty minutes later it has touched the test runner, the CI config and your package.json. Defenses: every loop needs a hard scope (*'only files matching tests/auth/**'*), a budget (*'stop after 8 tool calls'*), and a deliverable (*'write a 5-bullet summary at the end'*). Without all three, you are gambling.

Takeaways (memorize these)

Long unsupervised Claude loops drift; break work into small bounded tasks with explicit handoffs.
Parallel fan-out: independent sub-tasks run in parallel subagents, merge at the end. One-quarter wall clock, higher quality.
Artifact handoff: every agent writes a 500-word structured deliverable. The next agent reads only the artifact, never the stream.
Every long-running brief needs three constraints: scope, budget, deliverable. Without them you are gambling.
MCP and tool integrations expand power and risk together; never combine two unsafe capabilities without a human review gate.
