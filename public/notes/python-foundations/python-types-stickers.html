Variables Are Stickers, Not Boxes

Names point; they don't contain

notes by Aanya ✏️

~ 14 min read ~

Most Python bugs aren't logic bugs. They're *naming* bugs.

Mental model: stickers, not boxes
Other languages teach you that variables are *boxes* you put values into. Python isn't that. **Python names are stickers** you peel off and stick onto objects.

Move 1 — Name binding and rebinding

  • When you write `a = [1, 2, 3]`, Python creates a list object somewhere in memory and points the name `a` at it. When you then write `b = a`, Python does **not** copy the list.
  • Step 1 — Create the list, point a at it: One list object lives in memory. One name a points at it.
  • Step 2 — Alias: No copy happens. b becomes a second sticker on the same paper bag.
  • Step 3 — Mutate via b: The single underlying list grows by one. Both names see the change because both point at the same object.
  • Step 4 — Rebind b: b + [5] creates a NEW list. The = points b at the new list. a is unchanged because nothing rebound a.
  • Step 5 — The diagnostic: Look at the operator. = on the left of an assignment rebinds the name. Method calls or [] subscript-assignment mutate the object. They are visually similar; they do completely different things.

Move 2 — The mutable default trap

  • Every Python developer trips on this exactly once. Then they tell the next one.

Takeaways (memorize these)

Python names are stickers, not boxes — `=` aliases, it does not copy
Mutation (`.append`, `[i] = `, `.update`) changes the object both names see
Rebinding (`x = ...` on the LHS) makes a name point at a new object
Default arguments are evaluated once at function definition; never use `[]` or `{}` as a default
The None-sentinel pattern (`if x is None: x = []`) is the canonical fix
