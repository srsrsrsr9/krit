Functions Are Plug-In Tools

Sane signatures, single returns, scope without surprise

Most beginner Python functions look like *imperative scripts wrapped in `def`*. They take 7 arguments, mutate global state, return None, and require ten test runs to figure out what they do.

Mental model: the signature is a contract
When you write `def get_user(user_id: int) -> User:`, you're signing a contract. *Give me an int. I'll give you a User. I won't reach outside this box for state. I won't surprise you.*

Move 1 — Args, kwargs, and defaults that don't bite

  • Python function signatures are flexible. Too flexible, if you don't know the rules: - **Positional args** — required, in order: `def f(a, b)` - **Keyword args with defaults** — optional, callable by name: `def f(a, b=10)` - **`*args`** — capture extra positional args as a tuple.

Takeaways (memorize these)

A function signature is a contract — make it visible with type hints
Force keyword-only args (with `*`) for booleans and flags; positional booleans are illegible
Mutable defaults are bugs; use the None-sentinel pattern
Assigning to a name inside a function makes it local for the whole function — pass values in, don't reach for globals
`*args, **kwargs` is a tool, not a default — never use it just to avoid declaring a real signature
