Putting It Together: A Real Mini-Project

CSV in, JSON out, debugging discipline at every step

notes by Ishaan ✏️

~ 14 min read ~

Time to put four lessons together on something real. We're going to build the most common Python program in the working world: read a messy CSV, transform the rows, summarize, write JSON.

Mental model: read, transform, summarize, write
Every data-handling Python program is some version of this four-stage pipeline. The key insight: **80 percent of your bugs live at the boundaries** — reading a malformed CSV, writing a JSON the next program can't parse. Twenty percent live in the middle, where they're easy to test.

Move 1 — Read and validate at the boundary

  • Real CSVs are not the CSVs in tutorials. They have: - Inconsistent date formats (`2024-03-12`, `12/03/2024`, `Mar 12 2024`) - Empty cells where you expected numbers - Trailing whitespace in keys (`'name '` vs `'name'`) - Encoding issues (a stray `\ufeff` BOM at the start of the first column name) - Rows that are 8 columns when you expected 7 Don't try to handle all of this gracefully in the middle of your pipeline.
  • 1. English: Top 5 customers by total revenue last quarter — that is, January through March 2026 — exclude refunds.
  • 2. The grain + filter: Iterate orders. Filter to last quarter. Filter out refunds.
  • 3. Aggregate: Group by customer; sum amount. Counter or defaultdict.
  • 4. Top N: Sort by total descending, take 5.
  • 5. Output: Write JSON.
  • Where you are now — Five lessons in. You walked in copy-pasting Stack Overflow. You're walking out with a vocabulary: stickers vs boxes, mutable defaults, the four-part rewire of a function signature, container choice as a complexity decision, the four-stage pipeline, the boundary discipline.

Traps to flag for the exam

The classic trap: 'errors=ignore' as a fix: When you hit a UnicodeDecodeError, the lazy fix is `open(path, encoding='utf-8', errors='ignore')`. **Don't.** This silently drops bytes. The ₹ sign disappears. The 'café' becomes 'caf'. You don't know what you've lost.

Takeaways (memorize these)

Every Python data program is read → transform → summarize → write; bugs cluster at the boundaries
Validate at the boundary; raise loudly with a row number; never `errors='ignore'`
`utf-8-sig` for Excel CSVs; strip header whitespace; expect malformed rows
Read tracebacks from the FIRST frame in your code, not the last frame in a library
Don't 'try/except: pass' around the bug — fix the boundary that let bad data through
