Building an AI-Augmented Workflow

Define output → prototype → evaluate → instrument → iterate

notes by Ishaan ✏️

~ 16 min read ~

Most teams treat 'use AI' as a one-shot prompt experiment. Production AI is a feedback loop: define output → prototype prompt → evaluate against ground truth → instrument in production → iterate.

Mental model: the loop, not the prompt
Most AI work is treated as 'engineer a prompt'. Production AI is treated as 'engineer a loop'.

Move 1 — Define output, prototype prompt, evaluate

  • The first 3 stages of the loop, in detail. Define output spec.** Before any prompt: what *exactly* does the output look like?
  • 1. Define output: What does a 'good summary' look like? 5 bullets max, action items separated, decisions called out. Write the JSON schema.
  • 2. Prototype on real data: Take 10 actual meeting transcripts. Hand-write the 'right' summary for each. Iterate the prompt until output matches your hand-written for at least 7 of 10.
  • 3. Eval set: Take 50 different transcripts. Write 50 ground-truth summaries (~3-4 hours of work). Run the prompt; measure agreement.
  • 4. Bar: If hand-written-vs-AI agreement is >85%, ship to a beta cohort. If <85%, iterate the prompt or examples.
  • 5. Production data only AFTER eval: The eval set is your ground truth. Production traffic is your monitoring; you don't replace eval with production. Both stay in the loop forever.

Move 2 — The 14-day workflow audit

  • For AI workflows already in production, run a 14-day audit periodically. Three numbers, two minutes a week.
  • Where you are now — Five lessons in. You walked in with hype and uncertainty. You walk out with: a model (LLMs are fast pattern-matchers), the prompt API (R-C-T-F-E), the hallucination fix (RAG with citations), the tool-fit framework (volume × stakes × verifiability), and a 14-day audit loop.

Traps to flag for the exam

The classic trap: ship and forget: Most rolled-back AI features were shipped without a monitoring loop. Quality drifted; users started complaining; the team scrambled to figure out what changed. By the time the post-mortem was written, the cause was 'we don't know what changed because we weren't measuring.'

Takeaways (memorize these)

Production AI is a feedback loop, not a one-shot prompt — define output, prototype, evaluate, instrument, iterate
Output spec before prompt — if you can't write the schema, you don't understand the use case
Eval set on day 1 — 50-200 hand-labeled examples, frozen, used to measure every change
14-day audit catches drift before users do — three numbers, weekly, with alert thresholds
No eval = no launch, regardless of model quality or prompt sophistication
