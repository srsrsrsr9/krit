What an LLM Actually Is (And What It Isn't)

Next-token prediction, not magic

notes by Aanya ✏️

~ 14 min read ~

Most people using LLMs treat them as oracles — *ask, receive*. Some treat them as pattern-matchers.

Mental model: a very fast pattern-matcher with no memory of yesterday
An LLM is a function that takes a sequence of tokens and produces probabilities for the next token. It does this by recognizing patterns it's seen during training across the internet's worth of text.

Move 1 — Tokens, context, temperature in plain English

  • Three terms you'll meet constantly. In plain English: - **Tokens** — chunks of text the model sees.
  • 1. The question: You ask the same question twice and get different answers. Most people think the model is 'broken' or 'inconsistent'.
  • 2. Temperature is the lever: If temperature > 0, the model samples from a probability distribution — the same input produces different outputs by design.
  • 3. The fix for facts: For factual or structured tasks, set temperature to 0 (or as low as your API allows). The same input now produces the same output every time.
  • 4. The fix for creative: For creative work, you actively want variation. Temperature 0.7-1.0 produces output that doesn't feel templated.
  • 5. The diagnostic: If your output is too random: lower temperature. If it's too templated: raise it. The dial is per-call, not per-model.

Move 2 — What it CAN and CANNOT do

  • **Can do well** (and reliably): summarize structured documents, transform format A to format B, classify text into categories you provide, draft text in a style you provide examples of, explain concepts in different vocabularies, generate plausible code given clear specs, follow a list of rules consistently when the rules are explicit. **Can do reasonably** (with verification): research questions where the answer is on the public internet, complex reasoning when the steps are written out, code that requires multiple files (with tooling), data extraction from unstructured text.

Traps to flag for the exam

The classic trap: the 'magic black box': The single biggest source of bad AI features is treating the model as omniscient. Stakeholder asks 'can AI do X?' and the answer 'maybe, depends on…' gets compressed into 'yes' on the way to the demo.

Takeaways (memorize these)

An LLM is a next-token predictor — confident but not omniscient
Tokens, context window, temperature — three knobs that explain most of LLM behavior
Reliably good: summarize, transform, classify, draft in style
Cannot do reliably without retrieval: cite sources, exact math beyond ~5 digits, post-cutoff events
The fit isn't 'AI is good or bad' — it's 'this specific use case fits the model, this one doesn't'
