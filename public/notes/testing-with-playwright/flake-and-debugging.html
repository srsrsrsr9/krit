Killing Flakiness — Debugging the Hardest Failures

Flake is information you haven't decoded yet

notes by Karthik ✏️

~ 14 min read ~

There's an on-call engineer at a Bengaluru fintech who got paged at 3am because a Playwright test `await page.waitForTimeout(3000)`'d on a flow that, on AWS that night, took 3,200 milliseconds. The test went red.

Mental model: flake is information you haven't decoded yet
Most teams treat a flaky test as a bug *in the test*. Sometimes it is. More often, it's a bug in your **timing assumptions**: you assumed a network call always takes <500ms, the page always finishes hydrating in <200ms, the spinner always appears before the real content. The test passes 95% of the time because those assumptions hold 95% of the time. The other 5% is reality.

Move 1 — The trace viewer ritual

  • Playwright ships with a **trace viewer** — a step-by-step replay of every action, every locator query, every network request, every console message, with screenshots before and after each step. It's the single most valuable debugging tool in the ecosystem and most teams discover it three years too late.
  • 1. Test went red on PR #4421, retry #2: Locally it passes. Slack messages start: 'flaky test, can you re-run?'
  • 2. Open the artifact: Download `trace.zip` from the GitHub Actions artifact list.
  • 3. Find the failing step: Trace viewer shows: `await page.getByRole('button', { name: 'Place order' }).click()` waited 5 seconds, then timed out. Button never became enabled.
  • 4. Read the network panel: `POST /api/quote` returned 500 at 4.8s. The button is gated behind a successful quote.
  • 5. The actual bug: Quote API has a 1-in-200 race when the user changes shipping address mid-quote. *Not* a flaky test. A real production bug the test caught for you.

Move 2 — The deterministic-clock fix

  • A huge category of flake comes from **time**: tests that depend on `Date.now()`, animations that take a different number of milliseconds on different machines, debouncing that fires after exactly 300ms when CI is busy. The fix is not to add sleeps.

Traps to flag for the exam

The classic trap: the retry crutch: Setting `retries: 3` in `playwright.config.ts` and calling it a fix is the developer equivalent of pressing snooze. Each retry hides a real signal: the test failed, you didn't read the trace, you re-ran until it passed, and you shipped.

Takeaways (memorize these)

Flake is information you haven't decoded yet. Treat it as a signal pointing at a non-determinism, not noise to suppress.
The trace viewer ritual: when a test flakes, open the trace before doing anything else. Set `trace: 'on-first-retry'` in your config.
The deterministic-clock fix: for tests that depend on time, install `page.clock` and advance virtual time. Real clocks make flaky tests.
Mock the network with `page.route()` instead of relying on real third-party services for tests that don't need them.
Retries are a temporary band-aid for genuine infra noise, not a substitute for fixing the actual cause.
