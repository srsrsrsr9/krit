Playwright Fundamentals — Selectors and Waits

Auto-waits exist. Stop sleeping. Stop using CSS selectors built from BEM hell.

notes by Meera ✏️

~ 14 min read ~

Selenium veterans show up to Playwright and immediately write the same test they wrote in 2018: `await driver.findElement(By.css('.btn.btn-primary.checkout-btn-v2'))` followed by `await driver.sleep(3000)` followed by an assertion that lies because the page hadn't finished hydrating. Playwright doesn't need any of that, but the muscle memory is hard to break.

Mental model: Playwright auto-waits, stop sleeping
Every Playwright action — `click`, `fill`, `selectOption`, `expect(...).toBeVisible()` — does **actionability checks** before it runs. It waits for the element to be attached, visible, stable, enabled, and on top. It retries assertions until they pass or the timeout (default 5 seconds) hits.

Move 1 — getByRole over CSS

  • **CSS selectors are the problem, not the solution.** When you write `page.locator('.btn.btn-primary.checkout-v2')`, you're coupling your test to your designer's mood. Half your test failures will come from style refactors that did not change a single user-visible thing.
  • 1. The customer journey, in English: A user lands on the pricing page, clicks 'Start free trial', fills email and password, agrees to terms, and clicks 'Create account'.
  • 2. Find the role for each interaction: Click → button. Fill → textbox (with label). Toggle → checkbox. Final click → button.
  • 3. Use the visible name as the locator key: What does the human see on the button? 'Start free trial', 'Create account'. That's your name.
  • 4. The test now reads like the journey: If a non-engineer reads it aloud, they understand it. That's the test for whether your locators are right.
  • 5. Designer renames `.btn-primary-v3` to `.btn-cta-2026`. Test still passes.: Because the test never knew or cared about the class name. That's the whole point.

Move 2 — Web-first assertions

  • Playwright assertions like `expect(locator).toBeVisible()` are **web-first**: they automatically retry until the condition is true or the timeout expires. This is fundamentally different from `expect(value).toBe(...)` from a unit-testing library, which evaluates once and gives up.

Takeaways (memorize these)

Playwright auto-waits for elements to be actionable. If your test sleeps, your test is wrong.
Reach for getByRole first. CSS selectors are the problem, not the solution.
Web-first assertions (`expect(locator).to...()`) auto-retry. If you extract the value to a variable first, you've broken the retry loop.
The locator priority ladder: role → label → text → test ID → CSS, in that order. The bottom rungs should sting to use.
Tests that read like the user journey survive design refactors. Tests coupled to class names die in them.
