Prompting for Financials Without Hallucinating

Numbers are not text — verify every figure

notes by Vikrant ✏️

~ 13 min read ~

Prompting for blog posts is forgiving. If a model writes "the cat sat on the mat" instead of "the cat slept on the mat," the world keeps turning.

Mental model: numbers are not text — verify every figure
When a model produces text, errors are usually obvious or harmless — wrong tone, missed nuance, awkward phrasing. When a model produces numbers, errors are usually invisible and material. **A number that is wrong by one digit looks identical to a number that is right.**

Move 1 — Structured-output prompts

  • First named move. Stop asking for paragraphs.
  • Step 1 — Define the schema first: Before you write a single English word, write the JSON schema. Field names, types, required vs optional, format constraints (GSTIN is exactly 15 chars, dates are YYYY-MM-DD).
  • Step 2 — Wrap with a system prompt that demands strict adherence: 'You return JSON only. No prose, no markdown fences, no explanation. If a field cannot be extracted, return null. If the document is not a tax invoice, return {"error": "not_invoice"}.'
  • Step 3 — Add a citation field: Include a 'source_lines' array — the line numbers in the source document where each value came from. This is the audit trail at the row level.
  • Step 4 — Include 1 or 2 examples: Few-shot examples beat instructions. Show the model one good input/output pair. Watch the consistency improve immediately.
  • Step 5 — Validate on parse: Your code attempts to parse the JSON. If it fails — missing field, wrong type, GSTIN of wrong length — re-prompt or flag. Never silently accept malformed output.
  • Step 6 — Reconcile totals before trusting: Sum extracted taxable + IGST + CGST + SGST and compare with the model's 'total' field and the source-document total. If they don't match within ₹1, the row is flagged.

Move 2 — The 'show your sources' demand

  • Second named move. For every figure the model produces, demand a citation back to the source.

Traps to flag for the exam

The classic trap: the well-formatted hallucination: The most dangerous output is one that *looks* right. Clean tables, neat columns, GSTINs that pass format validation — and one number that is silently wrong by ₹54,000.

Takeaways (memorize these)

Numbers are not text. A wrong number looks identical to a right one; verification is non-negotiable.
Structured-output prompts make the schema a contract: malformed responses fail at parse time instead of in production.
The 'show your sources' demand turns invisible errors into visible ones; demand page/line/cell for every figure.
Format quality and number quality are uncorrelated; neat output can still be wrong by ₹54,000.
Always reconcile extracted totals against the source-document total before trusting any row.
