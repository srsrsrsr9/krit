Interaction Design and Microcopy

Every click is a question; every state change is the answer

notes by Karthik ✏️

~ 13 min read ~

Most interfaces are silent. You click, and you wait, and you wonder: did it hear you?

Mental model: every click is a question
When the user clicks, they are asking the interface a question: 'did this work?' The interface owes them an answer **inside 100 milliseconds**. Anything slower than that feels broken even if it isn't. The answer doesn't have to be the result; it just has to be acknowledgement that the question was heard. **A spinner inside 100ms is not a delay; it is a reply.**

Move 1 — State changes that confirm

  • Every interactive element should have **at least five states**, each visually distinct: 1. **Idle** — the rest state.
  • T+0ms — Click registered: Button enters pressed state immediately. Visual shift: slightly darker fill, slight depression. Cost: 10 lines of CSS.
  • T+50ms — Optimistic state: If the action is safe to assume success (a like, a star, a non-destructive toggle), update the UI immediately. Roll back on error.
  • T+200ms — Loading kicks in: If the request hasn't returned yet, swap label to 'Saving…' and add a spinner. Disable the button to prevent double-click.
  • T+2000ms — Progress indication: If still pending after 2s, change copy to 'Still working… this usually takes a few seconds.' Anxiety drops; abandonment drops.
  • T+resolved — Result state: Inline 'Saved' for routine; toast for cross-page actions; modal celebration only for genuine milestones. Match volume to importance.

Move 2 — Microcopy that defuses

  • Microcopy is every word in your interface that isn't the brand name or the body content. Buttons, labels, error messages, empty states, tooltips, placeholders, modal titles, system notifications.

Traps to flag for the exam

The classic trap: copying the placeholder: Junior teams ship microcopy that started life as Lorem Ipsum and got 'good enough' replacement text in week six. Three months later the dashboard's empty state still reads 'Welcome to dashboard' and the error message still says 'An error occurred.' **Microcopy is not done when it is grammatically correct; it is done when it does a job.** The job is to defuse user anxiety, name the next step, or convert a blank screen into onboarding. If your copy doesn't do one of those, rewrite it.

Takeaways (memorize these)

Every click is a question. The interface owes the user an answer inside 100ms — even if the answer is just 'I heard you.'
Five button states (idle, hover, pressed, loading, success/error) are the minimum. Most teams ship two.
Anything over 200ms needs a loading state; anything over 2 seconds needs progress indication.
Microcopy: name the verb (Save invoice, not Submit), name the cause in errors, treat empty states as onboarding.
Match the volume of feedback to the importance of the action. A like is a colour change; a milestone deserves a celebration.
