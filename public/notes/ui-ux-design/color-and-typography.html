Color and Typography Without the Cargo Cult

Type is a hierarchy of voices; color is a system of meanings

notes by Meera ✏️

~ 13 min read ~

Two design crimes happen on every junior team. The first: a designer picks 14 distinct font sizes 'because we need flexibility.' The second: an engineer pastes #FF0000 into the error toast component because Stack Overflow said red means error.

Mental model: type is a hierarchy of voices
Imagine your interface is a stage play. The H1 is the lead actor's line. The H2 is supporting cast. The body is dialogue. The caption is the stage direction nobody reads. **A type scale is the casting of voices for that play.** Six voices is a manageable cast; fourteen is a riot. Pick a ratio, derive the sizes, and refuse to add more without rewriting the whole script.

Move 1 — Pick a ratio, derive the scale

  • A type scale is built by multiplying. Pick a base size (16px is the universal default for body text on web; the world has agreed) and a ratio.
  • Step 1 — Set body size: 16px on web. 17 on iOS-influenced apps. Don't overthink.
  • Step 2 — Pick the ratio: 1.25 for SaaS, 1.333 for marketing, 1.2 for dense data tools. If you can't decide, ship 1.25.
  • Step 3 — Generate 5-6 sizes: Multiply, round to nearest pixel. Stop at 5-6; one for each H level plus body and caption.
  • Step 4 — Name them semantically: text-display, text-h1, text-h2, text-h3, text-body, text-caption. Numbers are tempting; names survive a redesign.
  • Step 5 — Document the line-heights: Use a separate scale for line-height: 1.5 for body, 1.3 for headings. The single biggest readability lever you have.

Move 2 — Tokens, not hex codes

  • Hex codes are technical debt. Every #3B82F6 you paste into a component is a future bug — when the brand changes, when dark mode lands, when accessibility fails, when a designer 'tweaks' it to #3D80F4 in one screen and forgets to update the others.

Traps to flag for the exam

The classic trap: branding the token names: Junior designers love naming tokens after the brand: `mahindra-orange`, `swiggy-red`, `paytm-blue`. It feels personal. It is also a guaranteed rebrand catastrophe. **Never name a token after a colour or a brand. Name it after the role it plays.** `interaction-default` could be navy today and saffron next year; `paytm-blue` is just a lie waiting to be found.

Takeaways (memorize these)

Pick a type-scale ratio (1.25 for SaaS) and derive 5-6 sizes. Six voices, not fourteen.
Body text on web is 16px. Anything below 14 is hostile to anyone over 35.
Line-height is the single biggest readability lever. 1.5 for body, 1.3 for headings.
Hex codes are technical debt. Use semantic tokens (interaction-default, feedback-error) so rebrands cost one diff.
Never name a token after a colour or brand. Name it after the role it plays.
